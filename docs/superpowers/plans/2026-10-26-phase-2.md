# Desktop Study Companion Phase 2 Implementation Plan

> Execution: superpowers:executing-plans, inline, with test-first domain logic and a final independent review. No commits, merges or pushes.

**Goal:** Complete the existing desktop student workspace while retaining the sidebar and Dashboard design.
**Architecture:** Shared typed models and pure validation; serialized atomic JSON storage and narrow IPC in Electron main; a subscribed React data provider and independent pages. Main owns reminders, timer and pet window.
**Tech Stack:** Existing Electron, React, TypeScript, lucide-react; Node test runner, no new dependencies.
**Spec:** User's Phase 2 specification, attached to this chat. Approved architecture: JSON persistence, existing D: repository.

## Global constraints

- All project files remain in D:\Projects\desktop-study-companion.
- Preserve existing design and unrelated work. Do not commit, merge or push.
- Runtime data uses Electron userData. Test data stays in an isolated project test directory.
- Notifications run only while the app runs. Imported events are local copies.
- No AI, network accounts, sync or advanced pet animation.

## Shared contracts

src/shared/models.ts: ClassSchedule, StudyTask, CalendarEvent, Reminder, FocusSettings, FocusSession, FocusPeriod, AppSettings, AppData, AppSnapshot, Command and CompanionAPI.
src/shared/validation.ts: validateData(unknown): AppData, validateCommand(unknown): Command.
src/main/store.ts: JsonStore.load(), read(), transact(updater); writes serialized, temp-file rename, corruption preserved.
src/shared/dates.ts: local dates and deadline helpers.
All pages consume AppSnapshot via src/renderer/src/state/CompanionProvider.tsx and dispatch typed commands. Main validates the resulting entire state before saving. Updates are broadcast to trusted windows only.

## Review focus

- Corrupt/future-version storage must not be silently overwritten (Stage 1 tests).
- Rapid commands must not lose edits (Stage 1 concurrent persistence test).
- DST, invalid dates, end-exclusive all-day imports and duplicate ICS events (Stage 2).
- Sleep/resume, paused periods, repeated reminder checks and rescheduling (Stage 3).
- Pet-only windows must have no unrestricted storage/notification capabilities (Stage 4 and review).
